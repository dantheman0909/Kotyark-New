# Kotyark on Wix Studio: front-end kit

**Wix stays the CMS and the host.** Wix manages pages, content, files and investor documents, and Wix
publishes the site. This kit carries the redesigned look (the Next.js site in `../src`, the visual reference)
onto the Wix Studio site.

| What | Where | Goes into the Wix site as |
|---|---|---|
| Design system (tokens, `k-` classes) | `src/styles/global.css` | `src/styles/global.css` (site-wide CSS) |
| Interactive pieces (Web Components) | `src/public/custom-elements/` | Custom Elements (Velo file source) |
| Page logic (Velo) | `src/public/pages/`, `src/public/lib/` | Imported by each Wix-generated page file |
| Backend (Velo web modules, jobs) | `src/backend/` | `src/backend/` |
| CMS collections | `data/collections/*.csv` | CMS > Import |
| Page-by-page build spec | `docs/page-build-spec.md` | What the designer builds in the editor |
| Class catalog, theme setup | `docs/design-system.md` | Site Styles + CSS Classes panel |
| CMS schema | `docs/cms-collections.md` | CMS collection settings |
| Custom elements guide | `docs/custom-elements.md` | Add Elements > Custom Element |
| Reference screenshots | `reference/` | Visual QA target (desktop 1440, mobile 390) |

---

## Why it works this way (Wix constraints)

- **Wix cannot run a Next.js app.** Layout is built in the Wix Studio editor; code (CSS, Velo, custom
  elements) syncs through Wix's Git integration.
- **"Connect to GitHub" creates a new repo owned by Wix's Velo app.** It does not adopt this one. The kit is
  copied into that repo with `scripts/sync-to-wix-repo.mjs`.
- **Page code files are generated by Wix** (`src/pages/<Page Name>.<id>.js`) when a page is created in the
  editor. They cannot be created or renamed by hand. So page logic lives in `public/pages/`, and each
  generated file only imports it (see `src/pages/README.md`).
- **After connecting to GitHub, the browser editor becomes read-only.** Design work continues in the
  **Local Editor** (`wix dev`). **Build the pages in the browser editor first, then connect GitHub.**
- **CSS reaches elements through classes only.** These are Wix global and semantic classes, plus custom
  `k-` classes that you assign in the CSS Classes panel.
- **Custom elements** need a Premium plan, a connected domain and no Wix ads. They render client-side, so
  every SEO-relevant text stays in native Wix elements. Investor documents are native repeaters on CMS
  collections, which keeps them in Wix's server rendering, sitemap and site search.

## Rollout plan

### Phase A: Prepare (no live impact)
1. **Duplicate the live site** in Wix Studio ("Kotyark – Redesign"). All work happens on the copy; the live
   site is untouched until cut-over.
2. **Theme:** set Site Styles colors and fonts to the tokens in `docs/design-system.md` (Plus Jakarta Sans,
   Inter; brand greens; neutrals).
3. **Media:** upload `../public/images/*` to Wix Media.
4. **CMS:** create the collections in `docs/cms-collections.md`. Then import `data/collections/*.csv` in
   this order: InvestorSections, then InvestorDocuments (it references sections), then Reg46Disclosures.
   Set permissions: read = Anyone, write = Admin.
5. **Fix the broken documents.** 96 of 104 legacy PDF links are broken (`data/source/link-audit-2026-10-15.csv`).
   In CMS > InvestorDocuments, upload the real PDF into the **file** field for each broken row. The page code
   prefers the uploaded file over `legacyUrl`.

### Phase B: Build the design (browser editor)
6. Follow `docs/page-build-spec.md` page by page. Create the pages with the **exact current URLs**. Build
   one **dynamic page** on InvestorSections at `/investors/{slug}`; it replaces the 14 separate section pages.
   Give elements the IDs listed in `src/pages/README.md`. Apply the `k-` classes from the spec.
7. Add the custom elements per `docs/custom-elements.md`, and fill each element's SEO markup.
8. Compare every page against `reference/*-desktop.jpg` and `*-mobile.jpg`.

### Phase C: Connect code
9. In the site's Code sidebar: **GitHub > Connect to GitHub**. Wix creates the repo and shows the setup commands.
   Run them (Node 20.11+). They clone the repo, run `npm install`, run `npm install -g @wix/cli`, and open `wix dev`.
10. From this repo, run `node wix/scripts/sync-to-wix-repo.mjs /path/to/wix-site-repo`. Use `--dry-run` first.
11. Paste the one-line import into each generated page file (`src/pages/README.md`).
12. Test in the Local Editor (`wix dev`). Commit and push to the Wix repo's default branch.
13. Run `wix preview` to get a shareable preview URL. Review it on desktop and mobile.

### Phase D: Go live
14. Run `wix publish` and choose **Latest commit from origin/main**. Publishing local code leaves the live site
    and the repo out of sync, so avoid it.
15. Cut over: either publish the redesigned copy and move the domain to it, or rebuild on the live site
    using the same steps. **Before moving the domain,** export the live site's existing 301 redirects
    (SEO > URL Redirect Manager) and recreate them on the new site.
16. After launch: check Search Console coverage, and check the sitemap (Wix generates it automatically,
    including the dynamic investor pages).

## Day-to-day after launch
- **Documents and content:** Wix dashboard > CMS. Nothing here needs to change.
- **Design or behaviour changes:** edit the kit in this repo. Re-run `scripts/sync-to-wix-repo.mjs`, then
  commit and push to the Wix repo, then run `wix publish`.
- **Layout changes:** make them in the Local Editor (`wix dev`), since the browser editor is read-only
  while GitHub is connected.

## Out of scope for Wix (kept only in the reference build)
The custom Postgres CMS, admin portal, users, audit log and own-domain `/files` URLs live on branch
`claude/sleepy-knuth-nrpw0g` (PR #1). On Wix, those roles belong to the Wix dashboard, Wix roles and
permissions, and Wix Media.
